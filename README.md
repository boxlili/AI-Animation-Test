# AI-Animation-Test
AI做动画，真的能改准“晚两帧出拳”吗？一份征集复现者的测试提案

正文
先说明：这是一份还没有人执行过的开源实验提案。我只提出问题和测试方法，文中所有的“预期”都是待验证的假说，不是最终结论。欢迎有条件的朋友认领、复现，也欢迎挑毛病。

数据、工程文件和结果都会汇总在我的GitHub仓库里：
https://github.com/boxlili/AI-Animation-Test

一、为什么想做这个测试

现在大部分AI视频是“一句话出片”：输入描述，直接生成一段视频。效果很惊艳，但它交付的是一整块不可修改的像素。导演如果说“这一拳晚两帧出”，你只能重新生成，然后祈祷别的地方别变。

动画、影视这类工业流程，要求的是能反复修改、能分工、能接进现有软件。所以业内正在走另一条路：先让AI在Blender这类软件里搭出可编辑的骨骼、关键帧和镜头（结构层），再交给视频模型做风格化渲染（渲染层）。

但有一个问题，我一直没看到有人认真测过：

动画的灵魂很大程度上在节奏。蓄力前的停顿、击中瞬间那一两帧的夸张变形，差一两帧，打击感就完全不一样。那么：

1. AI能不能按帧精确修改动画，并且只改该改的地方？
2. 在结构层调好的节奏，经过AI渲染之后还剩多少？

如果渲染层会把节奏抹平，那“结构可编辑”在动画领域就只解决了一半问题。

二、已经有人做过什么

BlenderWorld（阿里等团队近期发布）：223个真实任务，要求AI交付原生Blender工程。但这类工作主要评价场景和画面对不对。
Seedance 2.5（字节跳动）：支持用白模动画当参考生成成片，还能做局部编辑。
Blender Lab MCP Server（Blender官方）：让大模型可以直接操作Blender。

据我所知，“帧级的时间修改”和“渲染后节奏保留多少”目前还没有被系统测过。当然，没查到不代表没人做过，如果你知道相关工作，请在评论区告诉我。

三、要验证的五个假说

判定标准提前写好，以免跑完以后再改“成功”的定义。

H1意图层：AI能通过对话搭出基本可用的打斗动作和镜头。
判定：10轮对话以内搭出符合描述的动作，人工评审认为可用。

H2结构层：AI能按帧精确修改，而且只改目标部分。
判定：时间误差为0帧，误改率低于5%，3次重复中至少2次达到。

H3渲染层：生成式渲染会抹平帧级节奏。
判定：冲击帧偏移达到或超过1帧，或者停顿保持率低于70%，并且在多数试验中出现。

H4 2D（可选）：一拍二和残影帧在渲染后损失更大。
判定：2D镜头的各项保持率明显低于3D镜头。

H5对照：同样的修改，结构路线比像素直出路线改得更准、尝试次数更少。
判定：在时间误差和达标所需的尝试次数两项上，结构路线都优于像素直出路线。

四、测试需要什么

原则：不指定具体模型，但必须记录测试时用的版本和日期。

结构层：Blender当前稳定版；MCP服务（官方版或社区版均可）；至少2个支持MCP的大模型。
角色：两个人形角色，用Rigify绑定，并打开可拉伸选项（不建议用Mixamo，它的骨骼默认不能拉伸，会让形变测试因为资产问题失败）。
渲染层：R0（Blender视口预览基准）、R1（闭源API如Seedance 2.5）、R2（本地开源方案如ComfyUI）。每种渲染方式分别出二次元和写实两种风格。
安全提醒：Blender官方说明，MCP会直接执行AI生成的代码，没有任何防护措施。请在独立目录或虚拟机里操作，并提前备份。

五、五个测试镜头

所有镜头都是24帧每秒，时长约3秒。
S1直拳闪避（必选）：A从左冲向右打出右直拳，B向右闪避，侧面固定机位。考察基础的时间修改。
S2蓄力停顿（必选）：A后拉蓄力，停6帧，然后爆发出拳。考察停顿能否保留。
S3冲击帧（必选）：击中的1到2帧里手臂拉长、身体变形。考察非物理形变。
S4运镜（可选）：跟拍改成固定机位，再加一次震屏。考察镜头能否单独修改。
S5 2D打斗（可选）：用Grease Pencil制作，一拍二节奏，加一帧残影。考察2D作画的特性。

征集动画师：每个镜头最好有一份人工制作的“标准答案工程”。我自己不会做，如果你是动画师，愿意提供这部分，会是对这个测试最大的帮助。

六、测试流程

阶段1：搭建。让AI通过对话搭出镜头，记录对话轮数、工具调用次数和人工纠正次数。
阶段2：编辑。按顺序发出指令，每一条都在上一步的结果上继续。

1. 时间平移：“把A出拳击中那一帧往后推两帧。”
2. 停顿调整：“蓄力停顿从6帧延长到10帧，后面的动作整体顺延。”
3. 镜头解耦：“取消摄像机对A的跟随，改成固定机位。”
4. 局部修改：“只改A的右臂动作，B和镜头保持不动。”
5. 夸张形变：“击中那一帧，把A的右小臂拉长到原长度的1.5倍。”
6. 回溯：“撤回第1步的修改，其他修改保留。”
   阶段3：渲染。把每个版本分别送进R1和R2，二次元和写实风格各渲染一次。
   重复：每种组合重复3次。

七、怎么衡量

结构层：时间误差（目标关键帧实际帧号减去标准答案帧号）、误改率、形变达成度、回溯正确率、人工干预次数、成本。
渲染层：冲击帧偏移（用姿态估计工具提取轨迹对比）、停顿保持率、一拍二保持、形变保持、时间轴对齐。

八、怎么判断卡在哪一层

动作搭不出来：卡在意图层。
改A的时候B也跟着变：卡在结构层（没能只改目标部分）。
帧号改错：卡在结构层（状态管理）。
骨骼拉不长：卡在绑定或工具限制。
白模节奏对，渲染后出拳变软：卡在渲染层（时间结构被抹平）。
渲染后轨迹和透视对不上：卡在渲染层（空间一致性）。

九、为什么值得跑

如果H3成立（渲染会抹平节奏）：说明视频模型团队需要专门补强时间控制，创作者知道该在哪一步留人工检查。
如果H3不成立（节奏保住了）：说明这条路在节奏上已经可用，瓶颈在别处。
无论结果如何，都能补上现有测试的空白。
